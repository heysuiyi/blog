本期资料于北京时间2026年10月28日晨间核验，对应 UTC 10 月 27 日。期号日期、官方发布日期与资料核验日分别标明；连续学习部分依据当前官方文档，不把查阅文档的日期当作功能上线日期。

第5期从结束原因、工具结果校验和信息层级出发，学习判断结果是否可交付。本期向前补上任务进行中的一段：文字还在到达时怎样接收，用户按下停止后怎样收尾，等待时间如何分配，页面又该怎样解释内容尚未到达、没有结果或暂时失败。贯穿后三节的原则是：保存已有成果，停止不再需要的工作，给尚未确认的部分留下明确状态。

前两节先看可核验的科技与模型更新，随后进入配置、架构和UI的连续课程。后三节的业务场景和练习均为自拟示例；本期没有实际调用付费模型 API、连接真实业务系统或执行对外操作。

## 1 科研技术与科技新闻

### Oracle把企业工作流接入ChatGPT的计划

10 月 27 日，OpenAI 公布与 Oracle 扩大合作。Oracle 正在开发 AI Workspace，计划把业务应用与数据接入 ChatGPT，让员工在组织权限和审批约束下查找信息、完成获准的流程。公告还介绍了用 Codex 等工具构建应用的 App Composer；美国 Oracle 客户可通过 Oracle Marketplace 采购 OpenAI API、Codex 和 ChatGPT Work。这里需要区分：**采购入口已有明确可用范围，AI Workspace 的跨应用体验仍以开发目标描述**，不能把合作公告写成全部功能已经上线。[OpenAI 官方公告](https://openai.com/index/oracle-apps-in-chatgpt/)

**编辑观察：**这类整合的价值，要看原本分散的信息能否在同一任务中保持正确关联。例如设计团队查询某次展览的预算、采购与付款进度，界面既要说清查到了什么，也要保留数据来源、更新时间和可执行动作。聊天窗口能汇总记录，只解决了入口问题；是否允许修改预算或提交采购，仍需独立判断。评估时可先选只读流程，记录查错项目、遗漏记录和人工回查的次数，而不是仅比较回答速度。

### Unlimited OCR 2更新长文档解析方式

百度在 10 月 27 日宣布发布并开源 Unlimited OCR 2，同时邀请用户参加文档解析服务公测。官方披露的多页文档基准 MPDocBench 得分为 84.6、百页级 MarathonDocBench 为 77.1；这些是厂商报告，本刊没有复现。[百度发布公告](https://ai.baidu.com/support/news?action=detail&id=3290)

其模型卡把变化归于 SR-SWA，即稀疏参考滑动窗口注意力：把超长序列的图文交互压缩到固定规模的工作参考集合，以控制每一步解码的开销。**“无限页”不能读成任意文件都能零遗漏、零等待地解析。** 模型卡仍说明显存与并发配置的取舍，较小页面窗口还可能损害跨页内容合并。[官方模型卡](https://huggingface.co/baidu/Unlimited-OCR-2) 云服务还有另一层边界：当前官方 API 对 PDF 最多支持 500 页，并采用提交任务后查询结果的异步流程，不能把模型宣传直接套到托管服务上。[云 API 文档](https://cloud.baidu.com/doc/OCR/s/fmr1p39gb)

**编辑建议：**有长篇作品集、展览图录或扫描档案的团队，可用获准处理的样本建立验收集：特意保留跨页表格、脚注、双栏文字和低清扫描页，逐项检查阅读顺序与内容对应关系。除了算识字错误率，还应记录漏页、断表和人工修复时间。长文档一次请求能否成立，与解析结果能否直接进入知识库，是两个需要分别测量的问题。

## 2 新模型与产品特性

### Genie 4让生成的世界可以边运行边修改

Google DeepMind 于 **10 月 27 日公布 Genie 4**。这是一种实时交互世界模型：使用者可以在场景运行时输入文字改变天气、加入人物或调整镜头，模型继续生成环境如何变化，并原生生成环境声、音乐和交互对白。它把创作过程从等待一段固定视频，推进到边观察、边修改的短时模拟。[DeepMind 发布说明](https://deepmind.google/blog/genie-4-a-new-generation-of-world-simulation/)

这里的完整体验包含模型协作。官方说明，Gemini Omni 帮助模拟贴近现实外观与行为，其他 Gemini 模型参与推理、规划与连续性维持。不能把整套系统表现简化成一个模型独自完成全部工作，也不能据此认定已经获得可导出的游戏工程或精确物理仿真器。[Genie 4 模型说明](https://deepmind.google/models/genie/)

**可用性仍是研究预览。** 当前面向可信测试者；Google AI Ultra 订阅者在 Project Genie 中的使用，以及 Gemini API、Google AI Studio 早期合作伙伴的接入，被列为即将开放。付费订阅本身不等于已经取得 Genie 4 权限，本期也没有实际接入测试。[开放阶段说明](https://deepmind.google/blog/genie-4-a-new-generation-of-world-simulation/)

官方同时列出了实用边界：连续交互只支持数分钟；场景运行越久、复杂修改越多，物体与细节越可能漂移；真实地点还原、可读文字和实时音频准确性仍有限。因此，建议把它用于气氛、镜头路线与交互概念的早期讨论，不用生成画面证明真实空间尺寸、品牌字样或物理安全。[能力限制](https://deepmind.google/models/genie/)

**设计练习：**先在纸面写下一个展览入口的三次改动，例如改变光照、增加一位访客、转向入口背面；为每次改动列出“应当变化”和“必须保持”的对象。未来获得访问权限后，按这份清单比较生成结果，重点检查入口位置、导视文字和人物关系是否偷偷变化。交互生成降低了试想法的门槛，也让“哪些条件必须稳定”成为新的评审重点。

*核验说明：以上公告日期均按官方页面标注为 2026-10-27；本期于北京时间 2026-10-28 晨间核验。模型能力、成绩与开放状态来自官方材料，应用场景及练习为编辑建议，不代表实测结果。*

## 3 模型配置与使用

**本期学习目标：让文字可以提前阅读，也让中途停止有明确含义。** 上期讨论收到完整结果后怎样分流；今天处理结果尚在路上的情况。继续以 Claude Messages API 的 `claude-sonnet-4-6` 为教学对象，它目前属于 active legacy（仍可用的旧版）型号，不是最新型号推荐。本期补充固定核验基线：API 版本 `2026-10-21`、服务端 TypeScript SDK `@anthropic-ai/sdk` 1.3.0，不混用其他语言或云平台的接口。[型号状态](https://platform.claude.com/docs/en/models/sonnet-4-6/overview)、[SDK 1.3.0](https://github.com/anthropics/anthropic-sdk-typescript/releases/tag/sdk-v1.3.0)、[API 版本](https://platform.claude.com/docs/en/api/versioning)

### 接收的是事件 不是逐字到达的成品

请求输入仍是 `model`、`messages`、`max_tokens` 等参数，增加 `stream: true` 后，输出改为 SSE 增量事件。SDK 的 `client.messages.create({ …, stream: true })` 返回异步事件迭代器，不替应用累积最终消息；需要自行组织结果，或选用官方流式辅助接口。[Messages 请求](https://platform.claude.com/docs/en/api/messages/create)、[TypeScript 流式接口](https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/typescript#streaming-responses)

文本增量要按内容块 `index` 归位，不能把所有事件都拼成正文；工具输入中的 `partial_json` 可能只是半截字符串，应等完整内容块后再解析、校验，而不是猜齐参数执行。`ping` 不是生成完成，HTTP 连接成功后也可能收到流内 `error`。最后仍需确认 `message_stop`，再接回上期的结束原因与业务验收。另一个成本陷阱是把每次 `message_delta.usage` 相加：官方说明其中 token 数是累计值。[流事件与增量类型](https://platform.claude.com/docs/en/build-with-claude/streaming)

### 停止按钮要说明停止了哪一层

下面四层应分别记账，不能共用一句“全部取消成功”。前两层是应用与连接控制；后两层需要服务端或业务证据。

- **界面停止显示：**不再追加文字，但后端可能仍接收和处理。关闭页面也不能自动证明后端停止。
- **传输中止：**上述 SDK 原始流支持退出 `for await` 循环，或调用 `stream.controller.abort()`。这是取消该流的客户端机制，不是撤销业务动作的接口。[SDK 取消方法](https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/typescript#streaming-responses)
- **提供方任务取消：**若使用独立后台任务，必须遵守该任务的取消协议。例如 Claude Message Batches 的取消请求先令批次进入 `canceling`，不可中断的进行中请求仍可能完成；要查最终逐项结果，不能把批次接口套到普通 Messages 流上。[Batch 取消语义](https://platform.claude.com/docs/en/api/messages/batches/cancel)
- **业务动作撤销：**已发出的邮件、已写入的记录不会因断流自动消失。是否能撤销，要由业务接口、实际状态和授权另行决定。

因此，不能根据按钮已变灰或连接已关闭，承诺服务端立刻停算、费用归零。缺失最终用量时，记录“用量待确认”，再用提供方可用的用量记录核对；不拿屏幕上收到的字数冒充结算数。

### 虚构练习 用户在第六秒停止评审

输入是三款包装材料及“逐款给出优点、风险、建议”，不授权发布。收到第一款正文和第二款开头时，用户点击停止。建议应用先记录取消意图、停止安排后续工作，再中止对应请求；输出保留为“未完成草稿”，阻止提交，不自动接着生成。这是本文的应用设计，不是 SDK 自动提供的业务保证。

点击停止先记 `cancel_requested`；确认本应用的后续调度与本地工作已停止后，再记 `cancelled`；提供方状态若未确认，另外列为待核实。被动断流记为 `interrupted`。这些都是**自定义应用状态**，不是 Claude 的 `stop_reason`。若用户稍后要求继续，应建立新请求与新结果版本，不能无提示地把两次生成粘成一份已验收答案。流式展示适合聊天与草稿预览；要求完整 JSON、正式报告或驱动工具时，可以内部流式接收，但不要逐片提交。流式改善的是等待反馈，不保证整个任务更快或更便宜。

*适用范围：以上核验 Claude 直连 API 与指定 TypeScript SDK；未调用付费 API，未运行 SDK 示例。资料核验于 2026-10-28 北京时间（2026-10-27 UTC）；核验日期不是功能发布日期。*

## 4 架构设计

**本期学习目标：让整条任务共用一份时间预算，并把停止意图传到真正工作的地方。** 上一节解释了单次连接怎样结束，但一条评审流程可能还包括资料查询、重试和结果整理。上期的验收关口决定结果能否采纳；这次要让这些步骤也遵守同一个任务的期限与停止意图。以下预算、状态和时间线均为自拟设计推演，不是 Claude 的默认配置。

### 总期限限制等待 单步预算限制占用

总期限是这次任务最迟何时结束前台等待；单步预算是某个查询或生成最多可占多久。假设包装评审总预算 30 秒，预留 2 秒整理状态；每步启动前计算：

```text
可用时间 = 总期限 − 当前时间 − 收尾预留
本步预算 = min(该步骤上限, 可用时间)
```

可用时间不足就不启动下一步。服务进程内用单调时钟计算经过时长，避免系统校时改变预算；跨机器传递约定好的剩余时长，不能直接比较各机器的单调时钟读数。gRPC 官方文档也以扣除已耗时的 timeout 传播期限，避免机器时钟偏差；这里借用这一原则，不要求采用 gRPC。[期限与传播原则](https://grpc.io/docs/guides/deadlines/)

`timeout` 和重试次数还要单独理解：所选 SDK 的 `timeout` 单位为毫秒，`maxRetries` 控制重试，部分错误默认重试两次。单次配置不能代替整条工作流的总计时。重试等待、重试调用都消耗同一总预算，不能每试一次便重新获得 30 秒；应用应显式协调 SDK 与上层重试，避免两边各自重试。[固定版本请求选项](https://github.com/anthropics/anthropic-sdk-typescript/blob/sdk-v1.3.0/src/internal/request-options.ts)、[SDK 超时与重试](https://platform.claude.com/docs/en/cli-sdks-libraries/sdks/typescript#timeouts)

### 取消需要每一层配合

编排层的输入应包含任务编号、期限和取消信号；输出不仅有文本，还要有应用状态、停止原因及待核实事项。到时或用户停止后，编排层不再启动新步骤，把取消信号交给支持它的模型请求、查询和子任务。此 SDK 的请求选项提供 `signal: AbortSignal`；下游能否真正停止仍取决于各接口。耗时循环也要在安全点检查取消并释放资源，不能只让最外层停止等待。[SDK 信号选项](https://github.com/anthropics/anthropic-sdk-typescript/blob/sdk-v1.3.0/src/internal/request-options.ts)

这是协作式取消：请求取消与确认停止是两件事。gRPC 官方也明确指出，库通常不能强行打断应用处理函数，处理方需要主动检查取消。[取消传播边界](https://grpc.io/docs/guides/cancellation/) 对不支持取消的操作，应记录“仍待核实”，隔离它的迟到结果，防止旧任务覆盖用户后来启动的新任务。

### 同一评审任务怎样耗尽预算

下面只是纸面时间线，没有真实 API 延迟或计费含义：

```text
0 秒   接收只读评审任务：总预算 30 秒，预留收尾 2 秒。
4 秒   材料查询结束；生成上限设为 25 秒，实际只剩 24 秒可用。
28 秒  生成预算耗尽，发出取消信号，不再启动补写或工具调用。
30 秒  前台返回 timed_out 与未完成草稿；未确认停止的下游另列待核实。
```

`timed_out` 也是应用自定义状态，只表示等待预算耗尽，不能证明业务失败。主例没有外部写入；若换成一个**已另获授权**的发布流程，且发布请求发出后超时，就应保存操作编号并只读查询实际状态，确认已发布、未发布或仍未知。未知时不能直接重发，也不能告诉用户“已经撤销”；必要的撤回或补偿应另走授权流程。

### 哪些任务适合留在前台

短查询与可随时丢弃的草稿适合前台等待；耗时长、用户希望离开页面仍继续的工作，适合明确授权的后台任务。后台需要持久任务编号、可查询状态和独立取消入口，不能仅把前台 timeout 调大。关闭页面与取消后台工作最好提供不同操作；不支持进度估计时，就说明正在处理，而不是编一个百分比。

小测试：总预算还剩 3 秒，下一步至少需要 5 秒；用户又已点击停止。正确选择不是再试一次，而是不启动该步骤，保留草稿并呈现停止原因；若已有外部动作在途，则另外核对结果。**停止等待、停止计算和确认业务状态，要分别拿到证据。**

*适用范围：时间、任务与状态均为虚构设计。gRPC 引用为在线架构指南，不含特定语言 SDK 的实现承诺；资料核验于 2026-10-28 北京时间（2026-10-27 UTC）。*

## 5 大厂UI设计

**本期学习目标：让空白、等待和中断各有明确含义与下一步。** 前两节定义了应用状态，这一节把它们转成用户能够理解的反馈。上一期用信息层级帮助用户判断重点；这次处理内容尚未到达或无法完成时的界面。以下沿用虚构的设计工作室，设计一个“AI评审报告工作台”：左侧是报告列表，右侧是选中任务的草稿。先划清作用范围，列表没有匹配项，不代表右侧任务失败；某一章节失败，也不应清空整页。

### 空状态先说明为什么没有内容

[Ant Design 空状态规范](https://ant.design/docs/spec/research-empty-cn/)要求解释原因，并按场景提供建议操作；首次使用适合引导，用户完成或清空内容后则未必需要继续催促操作。本例据此区分三种情况：

- 首次使用且确实没有报告：写“还没有评审报告”，提供“选择素材，创建报告”。
- 查询成功但筛选结果为零：写“没有符合当前条件的报告”，保留可见的筛选条件，提供“清除筛选”，不要误导用户重新上传素材。
- 没有访问权限：写“你无权查看此项目”，提供实际可用的申请访问或切换项目入口，不显示“暂无数据”。[Ant Design 异常页规范](https://ant.design/docs/spec/research-exception/)把权限不足列为独立的错误情形。

这里的文案与分支是自拟设计。请求仍在等待时，也不能提前判为空；否则用户会把“尚未查到”误解为“确实没有”。

### 加载表达已知进展而非制造安心数字

[Material 3](https://m3.material.io/components/progress-indicators/guidelines)区分可确定与不可确定进度，要求前者准确反映所测量的进展，并让指示器的位置对应受影响区域。因此，本例未知生成时长时显示“正在整理包装评审”及不定进度提示，不编造“已完成90%”。“已读取2份，共3份”只能说明资料读取，不能冒充整份报告完成三分之二。

首次加载固定结构的列表，可用骨架提示将出现的位置；已有草稿继续生成时，则保留文字，在任务区显示状态。骨架不适合覆盖可读内容，持续等待也不应阻断查看其他报告。这些是本例的取舍，不是四套规范共同规定的秒数阈值。

### 错误提示要把恢复路径说具体

[Fluent 2 消息栏指南](https://fluent2.microsoft.design/components/web/react/core/messagebar/usage)要求信息清楚、可行动，并区分页面级与容器级范围。本例只在失败章节附近说明问题，其余草稿仍可查看。若连接断开但后台是否完成未知，写“连接中断，任务状态待确认；输入及已接收草稿已保留”，先提供“查看任务状态”，不要立刻声称生成失败。

恢复策略也要提前设计：确认失败后，才按系统能力提供“重试此章节”或“重新生成”；保留素材选择与要求。重试前核对原任务，或由服务端去重，避免连续点击创建多份报告。禁用重复提交按钮只是界面措施，不能替代后台保证。以上恢复流程是本课建议，不能把一个“再试一次”按钮当作所有故障的答案。

### 用户取消后仍要交代留下了什么

[Apple HIG](https://developer.apple.com/design/human-interface-guidelines/progress-indicators)建议在可行时允许停止处理，并告知丢失进度等后果。本例若能获得后台任务已停止的确认，点击“停止生成”后先显示“正在请求停止”，确认后才显示“已停止，保留2节未完成草稿”；若只是断开流，则写“已停止接收，后台状态待确认”。主动停止无需包装成红色系统错误，也不能显示“报告完成”。若无法保留内容，应在停止前说明；若系统不支持接续，就不要许诺“继续生成”。

### 不看颜色也能知道当前状态

[Fluent 2 颜色指南](https://fluent2.microsoft.design/color)要求颜色配合文字等线索；[Material 3 无障碍指南](https://m3.material.io/components/progress-indicators/accessibility)要求进度具有说明其用途的无障碍标签。本例可使用“正在生成包装评审”这样的状态说明，而非只有旋转图标。Fluent 消息栏也提醒避免过多强制播报打断操作；据此，本例只播报开始、阶段变化、完成或中断等有意义的变化，不把每个新生成的字都反复读出。

**自拟练习：**画出筛选无结果、连接中断、用户停止三张状态草图。请同事分别回答“现在发生了什么、哪些内容还在、下一步会做什么”。若三张都只剩“暂无数据＋重试”，就需要重新区分原因与行动。

## 今日小实验

做一张本地的“三款包装评审”页面，用假事件驱动即可，不需要连接真实 API。页面保留素材列表、评审草稿、任务状态和一个主要行动。先写状态规则，再画页面，避免为了配合某个漂亮的空状态而倒推业务含义。

准备四条事件记录。第一条：资料仍在读取，尚未得到查询结果；第二条：查询成功，但当前筛选条件下没有素材；第三条：评审已输出第一款的一段文字，用户点了停止，随后旧请求又迟到了一段文字；第四条：任务超过总期限，未拿到完整结果，但此前已经收到部分评审。这四条记录都不应显示“评审完成”，原因与下一步也各不相同。

**参考验收标准：**第一条说明正在读取，不能提前宣告“没有素材”；第二条解释当前筛选下无结果，并提供调整筛选的入口；第三条保留可复制的草稿，说明已按用户要求停止接收；若后台是否停止仍未知，就同时标明待确认，迟到事件不得重新启动任务或覆盖当前界面；第四条保留草稿、说明等待时间已到，并且不自动承诺后台工作已撤销。若准备重新生成，应创建新的任务标识，让旧任务的返回不能冒充本次结果。只有收到完整的结束证据并通过上一期的内容与业务验收，才进入可交付状态。

最后做两次检查：去掉颜色，能否只靠文字分清正在等待、无结果、用户停止和超时；快速重复“开始—停止—开始”，旧任务是否仍会篡改新任务的草稿。留下四张状态草图与一张事件记录，就能检验协议处理、架构约束和界面文案是否一致。这是本刊自拟练习，不是厂商的认证测试。

## 今天记住这四点

- 流式文字可以先展示，但在完整结束与验收前只能作为草稿。
- 用户取消、请求超时和接收中断要分别记录；任何一种都不自动证明外部操作已撤销。
- 任务应共享总期限，重试与收尾也要消耗同一份预算；迟到结果不能恢复已结束的任务。
- 加载表示尚在等待，查询无结果需要成功查询的证据，错误应说明影响范围与可行的下一步；不要让同一张空白页代替所有情况。
